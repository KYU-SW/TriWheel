# TriPle — AI 학습 기반 트리아지 판단 보조 시스템

> 응급실 근무 인력이 활력징후를 입력하면, 학습한 모델이 **트리아지 단계별 확률**을 바로 알려 주는 웹 프로그램

2026 창의설계 2 · **세바퀴** 팀

---

## 프로젝트 소개

응급실에서는 환자가 도착하면 트리아지 간호사가 KTAS(한국형 응급환자 분류도구)로 중증도를 5단계로 나눕니다.
이 판단은 짧은 시간 안에 반복해서 내려야 하고, 근무자의 경력과 상황에 따라 결과가 달라지기도 합니다.

TriPle은 트리아지 데이터로 학습한 모델을 이용해 **KTAS 1~5단계별 확률(%)**과 판단 근거를 함께 보여 줍니다.
시스템은 단계를 추천하지 않으며, 다섯 단계의 확률을 보고 간호사가 최종 단계를 정합니다.
이를 통해 근무 인력의 판단 부담과 피로를 줄이고, 효율적인 응급실 운영을 돕는 것이 목표입니다.

- **사용자**: 응급실 간호사 등 트리아지를 맡는 근무 인력
- **개발 기간**: 2026.09 ~ 2026.12
- **진행 방식**: 폭포수(Waterfall) 모델 — 제안 → 분석 → 설계 → 구현 → 시험 → 완료

> ⚠️ TriPle은 판단을 **보조**하는 도구입니다. 최종 트리아지 판단은 의료진이 내립니다.

## 주요 기능

| 기능 | 설명 |
| --- | --- |
| 활력징후 입력 | 한 화면의 입력창에 활력징후를 입력하고 판정 버튼을 누름 (입력 항목은 기본 활력징후로 시작해 이후 보완) |
| 단계별 확률 | KTAS 1~5단계 각각에 해당할 확률을 백분율(%)로 표시 |
| 판단 근거 | 위험 신호(Red flag) 해당 여부, 판단에 영향을 준 주요 항목 3개 표시 |
| 경고 표시 | 위험 신호가 있거나 입력값이 누락·범위 이탈이면 경고 문구 표시 (Red flag는 확률 값을 바꾸지 않음) |

로그인 없이 사용하며, 입력과 결과가 **한 화면**에 함께 나옵니다.

## 기술 스택

| 구분 | 내용 |
| --- | --- |
| 형태 | 웹 프로그램 (HTML 한 페이지) |
| 서버 | Python (FastAPI 또는 Flask — 설계 단계에서 확정) |
| 모델 | 부스팅 계열 분류 모델(현재 LightGBM으로 실험), 파일(.joblib)로 저장 — 최종 구성은 설계 단계에서 확정 |
| 학습 데이터 | 1단계 사전학습: 미국 공개 응급실 데이터(MIMIC-IV-ED 데모, Yale, NHAMCS 2022) / 2단계 학습·평가: 한국 KTAS 데이터(전문가 판정 1,267건) |
| 성능 지표 | 일치율(최고 확률 단계와 전문가 판정의 일치 비율), 과소·과대분류율, 중증(KTAS 1~2) 재현율 |
| 실행 환경 | 개발·시연: 팀원 로컬 PC / 운영: 병원 내부 서버 전제 |
| 협업 도구 | Microsoft Teams, Microsoft Project, GitHub |

## 처리 흐름

```
[화면] 활력징후 입력 ─▶ [서버] 입력 검증 ─▶ 전처리 ─▶ 모델 추론 ─▶ 결과 조합 ─▶ [화면] 단계별 확률·근거·경고
                                                                    ▲
                                              Red flag 규칙 검사 ───┘ (모델과 별도)

모델 파일(.joblib) ── 서버 시작 시 한 번 불러옴 (학습과 서버는 분리)
```

## 데이터 보안과 재학습

병원 내부에서는 이름이 없어도 활력징후와 판정 시각만으로 전자의무기록(EMR)과 대조해 환자를 특정할 수 있습니다.
그래서 TriPle은 **환자 기록을 따로 저장하지 않습니다.**

- **저장하지 않는 것**: 환자의 입력값, 판정 결과 (화면에 표시한 뒤 버림)
- **기록하는 것**: 개인정보가 없는 운영 지표만 (일별 판정 건수, 단계별 예측 분포, 오류 수)
- **재학습**: 운영 프로그램과 분리된 절차로 진행
  1. 병원 승인 절차를 거쳐 EMR에서 가명 처리한 데이터를 학습 데이터와 같은 형식으로 추출
  2. 재학습 스크립트로 학습한 뒤 고정된 시험 데이터로 검증
  3. 기준을 통과한 모델만 사람이 승인해 교체 (운영 중 자동 학습은 하지 않음)
  4. 모델 파일은 이름·날짜로 관리해 이전 모델로 되돌릴 수 있게 함
